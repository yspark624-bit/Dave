# 토큰 비용 가이드 — 무엇이 비싸고, 무엇이 공짜인가

> 목적: 대기(rate limit) 없이 매일 분석을 돌리기 위한 비용 구조 정리.
> 원칙 한 줄 — **계산은 파이썬이, 판단만 AI가.**

## 1. 비용 순위 (비싼 순)

| 순위 | 작업 | 1회 비용(대략) | 왜 |
|---|---|---|---|
| 1 | Webull MCP `get_stock_bars` 대량 호출 | 종목당 약 15,000토큰 | 250일치 OHLCV 원본이 통째로 문맥에 들어옴. 50종목 = 75만 토큰 |
| 2 | 서브에이전트 여러 개 동시 실행 | 에이전트당 전체 문맥 재로딩 | 에이전트는 차갑게 시작해 문맥을 처음부터 다시 읽음 |
| 3 | "폴더의 모든 파일을 요약" | 폴더 크기에 비례 | 요약하려면 전부 읽어야 함 |
| 4 | 한 세션에서 긴 대화 지속 | 턴마다 누적 재과금 | 매 턴 = 이전 대화 전체 + MCP 툴 목록 전체 재전송 |
| 5 | WebSearch / WebFetch | 1페이지 5,000~20,000토큰 | 웹페이지 원문이 그대로 들어옴 |
| 6 | `/loop`·크론 짧은 주기 반복 | 깨어날 때마다 전체 문맥 | 5분 주기 = 하루 288회 과금 |
| 7 | PDF/PPTX/DOCX 생성 스킬 | 스킬 문서 + 렌더링 | 스킬 본문이 문맥에 로드됨 |

## 2. 결정적 비교

같은 질문 "NVDA가 Stage 2인가?" 를 처리하는 두 가지 방법:

| 방식 | 문맥에 들어가는 것 | 토큰 |
|---|---|---|
| ❌ MCP로 일봉 250개 받아서 AI가 판단 | 원시 OHLCV 250행 | 약 15,000 |
| ✅ 로컬 스크립트가 계산, AI는 결과 1줄 | `NVDA Stage 2 8/8 RS 96 50MA +3.1%` | 약 40 |

**375배 차이.** 50종목이면 75만 토큰 vs 2,000 토큰.

## 3. 환경별 제약 (2026-09-13 실측)

| 환경 | 외부 시세 API (Yahoo/Stooq) | 결론 |
|---|---|---|
| Claude Code **웹/원격 세션** | ❌ 차단 (조직 네트워크 정책, HTTP 403) | Webull MCP 외 경로 없음 → 비쌈 |
| **본인 PC**의 Claude Code / Cowork | ✅ 가능 | 무료 데이터 수집 가능 → 여기서 돌릴 것 |

→ **데이터 수집과 계산은 반드시 본인 PC에서.** 웹 세션은 최종 판단·전략 논의 전용.

## 4. 절감 규칙 10가지

1. 원시 시세를 절대 AI 문맥에 넣지 않는다. `stage2_screen.py` 출력만 붙여넣는다.
2. Webull MCP는 **보유 종목 확인·주문 조회**에만 쓴다. 스크리닝에는 쓰지 않는다.
3. 스크리닝 대상은 감시 리스트(30종목 이내)로 제한한다. 전체 시장 스캔은 하지 않는다.
4. 서브에이전트는 사용자가 명시적으로 요청할 때만. 기본은 단일 세션.
5. 주제가 바뀌면 **새 세션**을 연다. 긴 세션을 이어가지 않는다.
6. 같은 질문을 반복하지 않는다. 결론은 `memory/lessons.md`에 적어 두고 참조한다.
7. `/loop`·크론은 **1시간 이상** 주기로만. 장중 5분 감시는 증권사 앱 알림으로 대체한다.
8. PDF는 AI에게 만들게 하지 말고 `make_report.py` → 브라우저 인쇄로 무료 생성한다.
9. 질문은 모아서 한 번에 한다. 짧은 왕복 10번 > 정리된 질문 1번 (비용이 몇 배 차이).
10. 파일 전체 요약 대신 "이 파일의 X 부분만" 처럼 범위를 지정한다.

## 5. 하루 예산 배분 (권장)

| 용도 | 비중 | 내용 |
|---|---|---|
| 로컬 스크립트 실행 | 0% | 데이터 수집·지표 계산·리포트 생성 — 전부 무료 |
| AI 판단 | 70% | 스크리닝 결과 표를 보고 매수/보유/청산 의견 |
| AI 심층 분석 | 25% | 후보 3종목 이내의 펀더멘털(실적·가이던스) 확인 |
| 예비 | 5% | 돌발 대응 |

이 구조면 **하루 소모 토큰이 기존의 1~3% 수준**으로 떨어집니다.
